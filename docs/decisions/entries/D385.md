## D385: `main` takes the full ruleset: pull request, resolved threads, `check` and `browser gate`

- Status: amends D175; replaces the interim ruleset of D384; amended by D387
- Date: 2026-11-09 (the owner chose the append-only start in D384; this is the step it named)
- Decision: `.github/rulesets/main.json` holds no deletion, no force push, linear history, a pull request with its review threads resolved and squash as the only merge method, and the required checks `check` and `browser gate`. No approval count (one owner cannot approve their own PR; code review is CodeRabbit, D143, D192), no bypass actor, and the branch need not be up to date at merge (the owner's call, kept off for the 4 to 15 minute CI wait it saves).
- Why: D300 step 5 (#776) stopped the engine committing `state/` to git, so no workflow pushes to `main` and a pull-request rule no longer fails an engine commit. `browser gate` (`ci.yml`) always runs and reports one name, so a ruleset can require the browser suites without hanging a docs PR.
- Consequences: a direct push to `main` is refused, including `docs: deploy now [deploy]`; a deploy goes through a PR whose squash title ends `[deploy]` (D375). A red `check` or `browser gate` blocks the merge. Dependabot's auto-merge (`automerge.yml`) waits for the same checks.
- Revisit if: a workflow must push to `main` again (add a bypass the platform accepts, or move the push to a PR), or an unrelated change merged without a rebase breaks `main` (turn on the strict up-to-date policy in the JSON and the ruleset).
