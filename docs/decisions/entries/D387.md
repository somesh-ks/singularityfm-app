## D387: `main` requires the branch to be up to date at merge

- Status: amends D385
- Date: 2026-11-09 (the owner, on a decision card: "Yes, as D175 decided")
- Decision: the ruleset for `main` sets `strict_required_status_checks_policy` to true. A pull request behind `main` is updated, and its checks rerun, before it can merge. Everything else in D385 stands.
- Why: a pull request tested against an old `main` can pass its checks and still break `main` once merged, and the rerun is the price of knowing it will not. D385 had left this off for the 4 to 15 minute wait; the owner chose the safer rule, which is also what D175 decided.
- Context changed: D385 kept the policy off as a convenience. The owner chose to pay the wait instead.
- Consequences: after any other merge, a waiting pull request needs an update and a rerun (about 4 minutes, 15 with the browser suites). `automerge.yml` prints a notice and leaves a behind pull request for a hand merge.
- Revisit if: the rerun wait after every other merge costs more than the broken-`main` risk it removes (set the policy to false in the JSON and the ruleset).
