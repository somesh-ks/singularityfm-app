## D389: An hourly check ships a merge the batch rule says is due

- Status: amends D375
- Date: 2026-11-10 (#735 merged on 11-06 with no merge after it and was not live when the owner checked; an agent had told him it ships within three hours)
- Decision: `.github/workflows/deploy-due.yml` runs every hour and by hand. It reads the live commit from the reader's `/build.json` and does nothing unless that commit is on `main` and is not `HEAD`. It then runs the reader's own `ignoreCommand` from `apps/web/vercel.json` as Vercel would for a push of `HEAD`, with doubt told apart from due, and only when that says due does it start the reader's Deploy Hook (the secret `VERCEL_DEPLOY_HOOK_WEB`). The batch rule stays in `scripts/deploy-batch.sh` alone. A session calls a merge live only once `vercel:list`, `vercel:inspect` or `/build.json` shows it.
- Why: the three hours were judged only when a push to `main` ran the check, and since D300 and D385 only a merge pushes to `main`, so a lone merge waited for the next one. Four docs-only `[deploy]` PRs in three days (#751, #767, #770, #778) shipped merges by hand.
- Context changed: D375 rejected a scheduled deploy as having "the same effect" as a push; with no push after a lone merge, the schedule is the missing trigger. A Deploy Hook starts only a build of `main`, so it needs no account-wide token.
- Consequences: a lone merge reaches production about four hours after it lands. The owner creates the hook (Vercel, the reader project, Settings, Git, Deploy Hooks, branch `main`), puts its URL in `.env` as `VERCEL_DEPLOY_HOOK_WEB` and runs `pnpm run secrets:push`; until then the check logs that the batch is due and does nothing. The PR adds a secret, so the owner merges it. The admin still waits for a push. The check does nothing on any doubt in the batch rule (`DOUBT_EXIT`) or for a head under 15 minutes old, and fires the hook at most once per commit in each six-hour window, so a failed build is retried up to four times a day until a fix merges. AGENTS.md drops "Vercel 100 deploys a day", Hobby's limit.
- Revisit if: admin lag matters (add its own hook), a failing build is retried long enough to show on the bill, or `site_behind` still warns about a lone merge after the hook is set.
