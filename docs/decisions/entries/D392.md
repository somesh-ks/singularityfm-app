## D392: The command center lives in its own private repository

- Status: amends D224, D382
- Date: 2026-11-13 (D382 step 6; the owner pointed the `singularity-admin` Vercel project at the new repository on 2026-11-12)
- Decision: amends D224, which made the command center a second app in this repository. `apps/admin` moves, with its history, to the private `somesh-ks/singularityfm-admin`, and this repository drops it, its browser job and its checks. The admin takes the design system and `@singularityfm/contracts` (the store readers, health rows and session cookie, compiled) from npm; this repository publishes contracts. At build it checks out this public repository's `apps/web/src`, `config/` and `apps/web/vercel.json` for Coverage, the Experiments flags and the headers its browser suite serves. The reader still rewrites `/admin` to that project's address.
- Why: the reader and the admin have separate owners' tools, deploys and review loads; one repository built and deployed both on every change, and the admin read the reader's folders by path, so a reader edit could break it unseen.
- Consequences: Coverage refreshes only when the admin deploys (a deploy hook from this repository's CI would fix that, a secret only the owner can add). A change to what contracts exports needs a version bump here and a pin bump there. `secrets:push` sends the admin's keys only from a linked checkout of that repository. The admin's stylesheets lose this repository's style test until the admin runs the design system's rules itself.
- Revisit if: the admin needs reader code that contracts cannot carry, or the cross-repository version bumps cost more than the shared build did.
