## D395: The site lives at news.someshks.com, and its address has one home

- Status: accepted
- Date: 2026-11-23
- Decision: the reader moved from news.someshks.work to news.someshks.com (owner, 23 Nov; `.work` answers 308 to `.com`). `site.json` at the repo root holds the address (`url`) and the hosts it left (`retired`). The site, the engine, `scripts/smokeLive.mjs` and the `smoke`, `health` and `deploy-due` workflows read it; no code names the host. Prose (docs, the digest skill, the change log) names it and is caught by the test on the next move. `scripts/siteDomain.test.ts` fails while a tracked file outside `docs/history/` and `docs/decisions/` names a retired host. The design-system and admin repos repoint by hand and point at `site.json`. The `deploy_rate` health message drops Hobby's 100-a-day cap (the team is on Pro since 13 Nov); its thresholds stay.
- Why: the move happened in Vercel while about 40 files still named `.work`, so smoke and health probed the 308 and filed #824 and #825 for two days. A hardcoded host in many places drifts on every move.
- Consequences: a move is one PR (runbook section 16) plus the clicks outside git. Records in `docs/history/` and `docs/decisions/` keep the old host as written. Per-origin state (favorites, queue, the installed app, push subscriptions) does not follow the redirect. Eleven test files changed their sample host with his OK.
- Revisit if: the admin or design system moves to its own host, or a second public host is added.
