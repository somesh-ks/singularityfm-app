## D397: The reader moves to singularityfm.app; the command center and the style guide get subdomains

- Status: active; amended by D398 (the player moves to play.singularityfm.app)
- Date: 2026-11-23
- Decision: the reader answers at `singularityfm.app`, the command center at `admin.singularityfm.app` and the style guide at `design.singularityfm.app` (owner, 23 Nov), each its own Vercel project at the root path. `site.json` holds all three (`url`, `admin`, `design`) and retires `news.someshks.com`, which with `news.someshks.work` redirects to the new host in Vercel. The reader's `/admin` and `/design` rewrites become redirects to the subdomains, as do `/analytics` and `/settings/health`. The command center keeps its pages same-origin with the reader's guarded `/api/health` and `/api/costs` by proxying those two paths to the reader in its own `vercel.json`; the host-only session cookie travels with the proxied request. Amends D395's address.
- Why: a domain of the product's own, and an admin and a guide that no longer share the reader's paths, base and service worker scope.
- Consequences: a session signed in on the old host signs in again; per-origin state (favorites, queue, the installed app, push subscriptions) starts empty on the new host; Simple Analytics needs the new site. The admin's proxy names the reader's host in its `vercel.json`, which `site.json` cannot reach; the admin repo's AGENTS.md lists it for the next move.
- Revisit if: the admin needs reader data beyond health and costs, which would argue for a typed API with CORS instead of a path proxy.
